## Absensi & Jadwal Shift + role Project Leader
Halaman `operator/absensi` = SATU lembar per unit+bulan (tanpa pilihan kelompok) seperti Excel: bagian atas **Kerja Shift** (pegawai ber-regu A-D = operator), bawah **Non Shift** (jabatan di `AttendanceRoster::NON_SHIFT_POSITIONS`: Project Leader, Koordinator Operasi/Pemeliharaan/K3, Office K3). Roster ditentukan HANYA oleh `App\Services\Operator\AttendanceRoster` (dipakai controller + AbsensiDocumentBuilder). Sel tetap disimpan per `work_schedules.group_type` (shift/non_shift); controller merutekan tiap sel ke roster pegawainya. "Isi Otomatis" (`operator.absensi.generate`) mengisi kedua roster: shift ikut pola regu dan MELANJUTKAN siklus dari 2 kode terakhir bulan sebelumnya (default fase A=0,B=6,C=2,D=4 pada OFF,OFF,S,S,P,P,M,M); non-shift P di hari kerja, OFF Sabtu/Minggu/libur nasional; kode absen (C/SKT/I/A) yang sudah ada TIDAK ditimpa. UI: kuas kode + klik/geser sel (tabel HTML biasa, bukan react-data-grid).
`AbsensiController` route `operator.absensi.{index,store,generate}`, permission `operator.absensi.view`/`.write`. Grant: Operator=view; **Project Leader** (`RoleName::ProjectLeaderOperasi`, role TERSENDIRI scope Unit = operator senior: semua permission operator + absensi.view/write + operasi.laporan.view)=write; TL Operasi=view+write; Manager UL=view. Project Leader adalah role sendiri (keputusan user), 1 operator per unit di-assign via DemoAccountSeeder (`project-leader.{slug}@upkendari.co.id`) — JANGAN pakai flag/label di user. Data: `work_schedules` unique(unit_id,year,month,group_type) + `work_schedule_entries` (1 sel = employee×tanggal, `attendance_code_id` nullable) — rekap & % kehadiran TIDAK disimpan, dihitung `App\Services\Operator\AttendanceCalculator` (present=code.hitung_hadir P/S/M ÷ scheduled=semua sel non-kosong termasuk OFF → rotasi bersih 6/8=0.75). Master global `attendance_codes` (P,S,M,OFF,C,SKT,I,A — "S"=Sore beda dgn "SKT"=Sakit) + per-unit `shift_patterns` (regu, sequence koma-pisah; generate opsional lalu tetap editable) via OperasiMasterRegistry (slug `attendance-codes`, `shift-patterns` — masih di master OPERASI walau dipakai modul Operator). `holidays` global (2026, indikatif) buat mewarnai kolom, TIDAK ubah shift. Pegawai dari master existing + kolom `employees.regu` (nullable; shift=regu terisi, non_shift=null). Cetak PDF: bukan react-data-grid (virtualized) — tabel HTML `.absensi-print` (hidden print:block) + trik visibility + `@page landscape`.

## Presensi (absen masuk/pulang) berbasis radius kantor unit
Absen masuk/pulang = `PresensiController` (route `operator.presensi.{index,check-in,check-out}`, permission `operator.presensi` → Operator & Project Leader) + `PresenceRecorder` (satu-satunya tempat hitung jarak haversine di server & aturan: 1 absen masuk per work_date WITA `Asia/Makassar`; absen pulang menutup absen masuk terbuka ≤20 jam, jadi shift Sore lewat tengah malam tetap 1 record). Tabel `employee_presences` (unique employee_id+work_date). Titik kantor per unit di `units.latitude/longitude/attendance_radius_m` (default 300) diatur menu `admin.attendance-locations` (gate `setting.manage` = Super Admin). User→pegawai via `employees.user_id`. Presensi TIDAK mengisi kode jadwal shift (work_schedule_entries) — keduanya terpisah kecuali user minta.

## Regu, Leader Shift, dan absen mengikuti Jadwal Shift
Regu (A–D, `AttendanceRoster::REGU`) + `employees.is_shift_leader` diatur di form Master Pegawai (keputusan user); `EmployeeRequest` menolak >1 Leader Shift aktif per unit+regu, dan leader wajib punya regu (tanpa regu → is_shift_leader dipaksa false). Jumlah anggota regu (2–4) TIDAK dibatasi. Absen masuk mencatat `shift_code` dari work_schedule_entries akun (`PresenceRecorder::currentShift`; mulai 20:00 WITA dengan jadwal besok = M → work_date besok) + `late_minutes` terhadap jam_mulai kode. Di luar shift kerja (OFF/cuti/belum dijadwalkan) absen TETAP boleh tapi `note` wajib (keputusan user). Tidak ada jendela jam absen.
